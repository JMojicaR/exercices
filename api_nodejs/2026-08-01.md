## Exercise 1: Notes API — Basic CRUD Endpoints

**Difficulty:** Basic

**Concepts:**
- Creating an Express server
- `express.json()` middleware for parsing JSON request bodies
- Route handlers: `app.get`, `app.post`, `app.put`, `app.delete`
- Route parameters (`:id`)
- In-memory array as data store
- HTTP status codes: `200` (OK), `201` (Created), `404` (Not Found)
- Sending JSON responses with `res.json()`

**Description:**
Build a simple Notes API that lets users create, read, update, and delete notes. Each note has an `id` (auto-assigned), `title`, and `content`. Store notes in an in-memory array — no database required. The server should listen on port 3000.

**Endpoints to implement:**
| Method | Path          | Description              | Success Status |
|--------|---------------|--------------------------|----------------|
| GET    | `/api/notes`  | Return all notes         | 200            |
| GET    | `/api/notes/:id` | Return a single note by ID | 200 (or 404) |
| POST   | `/api/notes`  | Create a new note        | 201            |
| PUT    | `/api/notes/:id` | Update an existing note | 200 (or 404) |
| DELETE | `/api/notes/:id` | Delete a note by ID    | 200 (or 404) |

const PORT = 3000;

## Summary

These three exercises build progressively:

1. **Notes API** — Core CRUD with in-memory array, route parameters, and `200`/`201`/`404` status codes.
2. **Products API** — Adds input validation and `400` status codes for bad requests.
3. **Contacts API** — Introduces query-string filtering, helper functions for clean route logic, and edge-case handling (empty search results).

All exercises use the same Express skeleton: `express.json()` middleware, route handlers on `app`, in-memory array storage with auto-incrementing IDs, and `app.listen()` on port 3000.
