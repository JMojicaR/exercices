## Exercise 1: Pydantic Model + GET Endpoints
**Difficulty:** Basic
**Concepts:** `FastAPI`, `BaseModel`, `@app.get`, path/query parameters, `HTTPException`

Define a `Reading` model and two GET endpoints (list all, get one by id).

**Starter code:**
```python
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

app = FastAPI()

class Reading(BaseModel):
    sensor: str
    value: float
    unit: str = "C"

readings = {
    1: Reading(sensor="temp", value=22.5, unit="C"),
    2: Reading(sensor="humidity", value=60.0, unit="%"),
}

@app.get("/readings")
def get_readings():
    return readings

@app.get("/readings/{reading_id}")
def get_reading(reading_id: int):
    if reading_id not in readings:
        raise HTTPException(status_code=404, detail="Reading not found")
    return readings[reading_id]
```

**Task:** Add a `?sensor=...` query parameter to `get_readings()` that filters the dict by sensor name before returning it.

## Exercise 2: POST + PUT with Validation
**Difficulty:** Basic
**Concepts:** `@app.post`, `@app.put`, request body via Pydantic, `Field` validation, `HTTPException`

Add `POST /readings` to create and `PUT /readings/{id}` to replace, with automatic body validation.

**Starter code:**
```python
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, Field

app = FastAPI()

class Reading(BaseModel):
    sensor: str
    value: float = Field(..., gt=-100, lt=200)
    unit: str = "C"

readings = {
    1: Reading(sensor="temp", value=22.5, unit="C"),
    2: Reading(sensor="humidity", value=60.0, unit="%"),
}

@app.post("/readings", status_code=201)
def create_reading(reading: Reading):
    new_id = max(readings.keys()) + 1
    readings[new_id] = reading
    return reading

@app.put("/readings/{reading_id}")
def update_reading(reading_id: int, reading: Reading):
    if reading_id not in readings:
        raise HTTPException(status_code=404, detail="Reading not found")
    readings[reading_id] = reading
    return reading
```

**Task:** Add a `min_length=1` constraint to the `sensor` field, and test that posting an empty `sensor` or an out-of-range `value` returns a `422` with a clear validation message.

## Exercise 3: DELETE + Filters + Error Handling
**Difficulty:** Basic
**Concepts:** `@app.delete`, `HTTPException`, query filters, `status_code`

Add `DELETE /readings/{id}` and a filtered list endpoint, with consistent error responses.

**Starter code:**
```python
from fastapi import FastAPI, HTTPException, Query
from pydantic import BaseModel, Field

app = FastAPI()

class Reading(BaseModel):
    sensor: str
    value: float = Field(..., gt=-100, lt=200)
    unit: str = "C"

readings = {
    1: Reading(sensor="temp", value=22.5, unit="C"),
    2: Reading(sensor="humidity", value=60.0, unit="%"),
}

@app.delete("/readings/{reading_id}")
def delete_reading(reading_id: int):
    if reading_id not in readings:
        raise HTTPException(status_code=404, detail="Reading not found")
    deleted = readings.pop(reading_id)
    return {"message": f"Deleted reading {reading_id}", "reading": deleted}

@app.get("/readings")
def list_readings(sensor: str = Query(None), min_value: float = Query(None)):
    result = readings
    if sensor is not None:
        result = {k: v for k, v in result.items() if v.sensor == sensor}
    if min_value is not None:
        result = {k: v for k, v in result.items() if v.value >= min_value}
    return result
```

**Task:** Add a global exception handler with `@app.exception_handler(HTTPException)` that wraps every error in `{"error": {"status_code": ..., "detail": ...}}`, and verify it fires for a 404.
