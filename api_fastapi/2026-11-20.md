Sources: FastAPI docs, fastapi.tiangolo.com tutorials

Theme: **Dictionary-Backed CRUD API with Pydantic** — a sensor-readings store held in an in-memory `dict` keyed by `id`, with GET/POST/PUT/DELETE endpoints, Pydantic models, validation, and `HTTPException` error handling.

Install with `pip install "fastapi[standard]"` and run with `uvicorn app:app --reload`. Interactive docs are at `http://127.0.0.1:8000/docs`.

## Exercise 1: GET Endpoints (List + By ID)
**Difficulty:** Basic
**Concepts:** `@app.get`, Pydantic `BaseModel`, path parameters, returning dicts, `HTTPException`

Define a `Reading` model and serve the dictionary of readings, fetching one by `id`.

**Starter code:**
```python
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

class Reading(BaseModel):
    sensor: str
    value: float

app = FastAPI()

readings = {
    1: {"sensor": "temp", "value": 21.5},
    2: {"sensor": "humidity", "value": 45.0},
}

@app.get("/readings")
def list_readings():
    return readings

@app.get("/readings/{reading_id}")
def get_reading(reading_id: int):
    reading = readings.get(reading_id)
    if reading is None:
        raise HTTPException(status_code=404, detail="Reading not found")
    return reading
```

**Task:** Add a query parameter `sensor: str | None = None` to `list_readings` that filters results by sensor name.

## Exercise 2: POST & PUT (Create & Update)
**Difficulty:** Basic
**Concepts:** `@app.post`, `@app.put`, Pydantic validation, `Field` constraints, `status_code=201`

Create new readings with a validated body, and update existing ones.

**Starter code:**
```python
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, Field

class Reading(BaseModel):
    sensor: str
    value: float = Field(gt=-50, lt=100, description="Reading value")

app = FastAPI()

readings = {
    1: {"sensor": "temp", "value": 21.5},
}

@app.post("/readings", status_code=201)
def create_reading(reading: Reading):
    new_id = max(readings.keys(), default=0) + 1
    readings[new_id] = reading.model_dump()
    return {"id": new_id, **readings[new_id]}

@app.put("/readings/{reading_id}")
def update_reading(reading_id: int, reading: Reading):
    if reading_id not in readings:
        raise HTTPException(status_code=404, detail="Reading not found")
    readings[reading_id] = reading.model_dump()
    return readings[reading_id]
```

**Task:** Send a body with `"value": 999` and confirm FastAPI returns a `422` validation error because of the `gt`/`lt` constraints.

## Exercise 3: DELETE + Error Handling
**Difficulty:** Basic
**Concepts:** `@app.delete`, `HTTPException`, removing keys safely, response messages

Delete a reading and return a confirmation, raising a 404 when the id is missing.

**Starter code:**
```python
from fastapi import FastAPI, HTTPException

app = FastAPI()

readings = {
    1: {"sensor": "temp", "value": 21.5},
    2: {"sensor": "humidity", "value": 45.0},
}

@app.delete("/readings/{reading_id}")
def delete_reading(reading_id: int):
    removed = readings.pop(reading_id, None)
    if removed is None:
        raise HTTPException(status_code=404, detail="Reading not found")
    return {"deleted": reading_id, "remaining": len(readings)}

@app.get("/readings/stats/total")
def total_readings():
    return {"total": len(readings)}
```

**Task:** Confirm that `DELETE /readings/999` returns `404`, and that `/readings/stats/total` still works after a deletion. Note that a route like `/readings/stats/total` must be declared before `/readings/{reading_id}` to avoid being swallowed by the path parameter.
