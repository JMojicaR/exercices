# Erlang — Basic Exercises (2026-11-15)
Sources: Learn You Some Erlang, erlang.org, tutorialspoint

Theme: **Error Handling** — `try`/`catch`, the exception classes `error`/`throw`/`exit`, the `after` clause for cleanup, and wrapping operations that can fail (like `list_to_integer/1`).

## Exercise 1: try/catch — error Class
**Difficulty:** Basic
**Concepts:** `try ... catch`, the `error` class, `badarith`, returning a tagged error tuple

Catch the arithmetic error raised by dividing by zero.

**Starter code:**
```erlang
-module(ex1).
-export([safe_divide/2]).

safe_divide(A, B) ->
    try
        A / B
    catch
        error:badarith -> {error, division_by_zero}
    end.
```

**Usage (erl shell):**
```erlang
1> c(ex1).
2> ex1:safe_divide(10, 2).
5.0
3> ex1:safe_divide(10, 0).
{error,division_by_zero}
```

**Task:** Add a clause that returns `{error, not_numbers}` when `safe_divide` is called with non-numeric arguments (catching the `error:badarith` those also raise).

## Exercise 2: try/catch — throw Class
**Difficulty:** Basic
**Concepts:** `throw/1`, `catch throw:Reason`, validating input by throwing a tagged value

Validate an argument by throwing a tag and catching it.

**Starter code:**
```erlang
-module(ex2).
-export([validate_age/1]).

validate_age(Age) ->
    try
        case Age < 0 of
            true  -> throw(negative_age);
            false -> {ok, Age}
        end
    catch
        throw:negative_age -> {error, "age cannot be negative"}
    end.
```

**Task:** Add a `throw(too_old)` branch for `Age > 150` and a matching `catch` clause returning `{error, "age is unrealistically high"}`.

## Exercise 3: try/catch — exit Class
**Difficulty:** Basic
**Concepts:** `exit/1`, `catch exit:Reason`, distinguishing `exit` from `error`/`throw`

Catch an explicit `exit` signal inside a `try`.

**Starter code:**
```erlang
-module(ex3).
-export([demo/0]).

demo() ->
    try
        exit(bad_state)
    catch
        exit:Reason -> {caught_exit, Reason}
    end.
```

**Task:** Add a second clause that calls `exit(normal)` and observe that `normal` is *not* caught by the `catch` block (it exits silently) — then explain why.

## Exercise 4: try ... after
**Difficulty:** Basic
**Concepts:** `after` clause, guaranteed cleanup, order of evaluation

Run cleanup code whether or not the `try` block raises an error.

**Starter code:**
```erlang
-module(ex4).
-export([demo/0]).

demo() ->
    try
        io:format("working...~n"),
        error(badarith)
    catch
        error:Reason -> {caught, Reason}
    after
        io:format("cleanup always runs~n")
    end.
```

**Task:** Replace `error(badarith)` with a successful expression and confirm the `after` clause still prints the cleanup message.

## Exercise 5: Error Handling in List Processing
**Difficulty:** Basic
**Concepts:** `lists:map/2`, `list_to_integer/1`, `error:badarg`, per-element try/catch

Parse a list of strings, tagging each failure instead of crashing the whole map.

**Starter code:**
```erlang
-module(ex5).
-export([parse_all/1]).

parse_all(Items) ->
    lists:map(fun parse/1, Items).

parse(Item) ->
    try
        {ok, list_to_integer(Item)}
    catch
        error:badarg -> {error, {not_an_integer, Item}}
    end.
```

**Usage:**
```erlang
1> ex5:parse_all(["10", "abc", "5"]).
[{ok,10},{error,{not_an_integer,"abc"}},{ok,5}]
```

**Task:** Add `lists:filter/2` logic (or a list comprehension) to return only the successfully parsed integers, discarding the `{error, _}` tuples.
