## Exercise 1: try/catch Basics
**Difficulty:** Basic
**Concepts:** `try`, `catch`, `throw new Error`, `err.message`

Write a `safeDivide` function that throws on division by zero and catches its own error.

**Starter code:**
```javascript
function safeDivide(a, b) {
  try {
    if (b === 0) {
      throw new Error("Cannot divide by zero");
    }
    return a / b;
  } catch (err) {
    return err.message;
  }
}

console.log(safeDivide(10, 2)); // 5
console.log(safeDivide(10, 0)); // Cannot divide by zero
```

**Task:** Also handle the case where `a` or `b` is not a number by throwing a `TypeError`, and return its message the same way.

## Exercise 2: try/catch with JSON.parse
**Difficulty:** Basic
**Concepts:** `JSON.parse`, `try`/`catch`, `console.error`, returning `null` on failure

Parse JSON safely so invalid input returns `null` instead of throwing.

**Starter code:**
```javascript
function parseUser(jsonString) {
  try {
    return JSON.parse(jsonString);
  } catch (err) {
    console.error("Invalid JSON:", err.message);
    return null;
  }
}

console.log(parseUser('{"name": "Ana", "age": 30}'));
console.log(parseUser("{not valid json}"));
```

**Task:** Extend the function to return `null` as well when the parsed object is missing a `name` property.

## Exercise 3: The finally Block
**Difficulty:** Basic
**Concepts:** `finally`, guaranteed cleanup regardless of success or failure

Demonstrate that cleanup code runs whether or not an error is thrown.

**Starter code:**
```javascript
function readConfig() {
  try {
    console.log("Loading config...");
    throw new Error("config file missing");
  } catch (err) {
    console.log("Caught:", err.message);
  } finally {
    console.log("Cleanup always runs");
  }
}

readConfig();
```

**Task:** Add a second function that does *not* throw, and show that its `finally` block still runs after the `try` block completes normally.

## Exercise 4: Custom Error Subclass
**Difficulty:** Basic
**Concepts:** `extends Error`, `super`, setting `this.name`, `throw`

Create a `ValidationError` class and throw it from a validation function.

**Starter code:**
```javascript
class ValidationError extends Error {
  constructor(message) {
    super(message);
    this.name = "ValidationError";
  }
}

function validateAge(age) {
  if (age < 0) {
    throw new ValidationError("Age cannot be negative");
  }
  return age;
}

try {
  validateAge(-3);
} catch (err) {
  console.log(`${err.name}: ${err.message}`);
}
```

**Task:** Add a check that throws `ValidationError` when `age > 150`, and print its name and message.

## Exercise 5: instanceof Checks + Rethrow
**Difficulty:** Basic
**Concepts:** `err instanceof`, `throw` (rethrow), handling only expected errors

Handle expected `TypeError`s while rethrowing anything unexpected.

**Starter code:**
```javascript
function process(data) {
  try {
    if (typeof data !== "object" || data === null) {
      throw new TypeError("data must be an object");
    }
    return data.value * 2;
  } catch (err) {
    if (err instanceof TypeError) {
      console.log("Type problem:", err.message);
    } else {
      throw err; // rethrow unexpected errors
    }
  }
}

console.log(process({ value: 21 }));
console.log(process("not an object"));
```

**Task:** Add a check inside the `try` that throws a `RangeError` when `data.value > 100`, and confirm it is rethrown (not caught) by the existing `catch`.
