# Rust — Basic Exercises (2026-11-15)
Sources: The Rust Book, Rust by Example, Programiz (Rust)

Theme: **Error Handling with Result & Option** — `Option<T>`/`Result<T, E>`, `match`, `unwrap`/`expect`, the `?` operator, and fallback helpers like `unwrap_or`. Rust has no exceptions; errors are values you must handle.

## Exercise 1: Option<T> with match
**Difficulty:** Basic
**Concepts:** `Option<T>`, `Some`/`None`, `match`, `enumerate`

Return `Some(index)` when a value is found, `None` otherwise, and match on the result.

**Starter code:**
```rust
fn find_index(items: &[i32], target: i32) -> Option<usize> {
    for (i, &item) in items.iter().enumerate() {
        if item == target {
            return Some(i);
        }
    }
    None
}

fn main() {
    let nums = [10, 20, 30];
    match find_index(&nums, 20) {
        Some(i) => println!("Found at index {}", i),
        None => println!("Not found"),
    }
}
```

**Task:** Also search for a value that isn't present (e.g. `40`) and confirm the `None` arm prints.

## Exercise 2: Result<T, E> with match
**Difficulty:** Basic
**Concepts:** `Result<T, E>`, `Ok`/`Err`, returning a `String` as the error type

Return `Err` for an invalid division and handle both cases with `match`.

**Starter code:**
```rust
fn divide(a: f64, b: f64) -> Result<f64, String> {
    if b == 0.0 {
        return Err(String::from("division by zero"));
    }
    Ok(a / b)
}

fn main() {
    match divide(10.0, 0.0) {
        Ok(result) => println!("Result: {}", result),
        Err(e) => println!("Error: {}", e),
    }
}
```

**Task:** Call `divide(10.0, 2.0)` and confirm the `Ok` arm prints `Result: 5`.

## Exercise 3: unwrap and expect
**Difficulty:** Basic
**Concepts:** `.unwrap()`, `.expect()`, panicking, `parse`

Extract the value from `Ok`/`Some`, with a custom panic message via `expect`.

**Starter code:**
```rust
fn main() {
    let parsed: i32 = "42".parse().unwrap();
    println!("Parsed: {}", parsed);

    let parsed2: i32 = "42".parse().expect("should be a valid number");
    println!("Parsed: {}", parsed2);
}
```

**Task:** Change the second parse to a non-numeric string and observe that `.expect(...)` panics with your custom message — then explain why `unwrap`/`expect` should be used sparingly.

## Exercise 4: The ? Operator
**Difficulty:** Basic
**Concepts:** `?`, propagating `Err` early, `ParseIntError`, `Result` return type

Use `?` to short-circuit out of a function when a parse fails.

**Starter code:**
```rust
fn parse_and_double(text: &str) -> Result<i32, std::num::ParseIntError> {
    let n: i32 = text.parse()?;
    Ok(n * 2)
}

fn main() {
    match parse_and_double("21") {
        Ok(v) => println!("Result: {}", v),
        Err(e) => println!("Parse error: {}", e),
    }
}
```

**Task:** Call `parse_and_double("hello")` and confirm the `Err` arm prints the parse error instead of panicking.

## Exercise 5: unwrap_or and Graceful Fallbacks
**Difficulty:** Basic
**Concepts:** `.unwrap_or()`, `ok()`, turning a `Result` into an `Option`, fallback values

Provide a default value instead of panicking when parsing fails.

**Starter code:**
```rust
fn main() {
    let parsed: i32 = "hello".parse().unwrap_or(0);
    println!("Fallback value: {}", parsed);

    let maybe: Result<i32, _> = "7".parse();
    match maybe {
        Ok(v) => println!("Got {}", v),
        Err(e) => println!("Error: {}", e),
    }
}
```

**Task:** Use `parse::<i32>()` on several strings in a loop, collecting every value with `unwrap_or(-1)`, and print the resulting vector.
